# v0.1权限、步骤与验收建议

建议规格，尚未实施。当前代码只具备旧简化状态机/编辑demo权限；不能从本表推断已经开放这些功能。

## 逐关负责人

| 当前关口/任务 | 可准备/执行者 | 必须由谁确认后生效 | 输出与下一步 |
|---|---|---|---|
| 作者准备稿 | 作者/明确授权代理，AI可提取候选字段 | 投稿人核对完整作者顺序/文件/必需声明 | 冻结提交版本；编辑部预审待办 |
| 完整性预审 | 分派编辑部人员，AI整理缺项 | 当前负责人 | 通过或退回补交；报告绑定版本 |
| 相似度报告复核 | 负责人上传合成/人工报告，AI仅摘要 | 当前负责人明确评估报告覆盖的文件hash | 不自动宣告学术不端；新文件使旧结论不再可用 |
| 材料/匿名筛选 | 当前预审负责人 | 当前负责人 | 确认审稿材料与可见范围 |
| 主编范围初筛 | 主编；作者本人即使兼主编仍有COI限制 | 具备本稿决定/范围权限的主编 | 转分派或准备正式退稿提案，不能直接发信 |
| 责任编辑分派 | 主编 | 主编确认目标编辑和责任范围 | 新assignment+编辑质量任务；旧分派结束保留历史 |
| 编辑质量/送审 | 当前责任编辑 | 责任编辑 | 创建版本固定的review_round；生成找人任务 |
| 站内邀请准备 | 责任编辑，AI可准备文案/候选理由 | 责任编辑确认受邀人、材料、COI、期限 | 邀请箱记录，不等于邮件已发 |
| 邀请响应 | 该邀请的目标审稿人 | 本人接受/拒绝及冲突声明 | 接受才产生分派；拒绝不计有效人数 |
| 评审报告 | 已接受分派的审稿人 | 本人独立审核完整报告后提交 | 冻结author-visible/editor-private分区报告 |
| 编辑汇总 | 当前责任编辑 | 本人确认建议与作者可见材料 | 主编决定待办；建议不改变录用状态 |
| 修回/接受/拒稿决定 | 主编/有明确决定分派的负责人；排除作者COI | 有权决定者审核不可变快照 | 内部决定记录；作者通知与邮件批准分开 |
| 作者修回 | 本稿作者 | 投稿负责人确认新版本/回复 | 保留旧版本和报告，产生复核/下一轮任务 |
| 制作/校样 | 分派出版人员/作者分别处理各自任务 | 各自负责人 | 制作包绑定接受版本与文件hash；校样变更重新确认 |
| 本地预览 | 分派出版人员 | 有权负责人确认本地预览快照 | 需登录的local_preview；不自动公开、发信或注册DOI |

首版主状态单值来源于确定性策略：找人/等待回复阶段可已有部分评审在做；有效接受人数和报告数不足时仍显示阻塞原因，不能用最近一行邀请status决定整稿阶段。修回不是把第一轮任务状态重置为pending，而是新版本/步骤周期/轮次。

## 各角色可见投影

| 角色 | 可见/可做 | 必须不能获得 |
|---|---|---|
| 作者 | 有明确所有权/授权的稿件，已发布给作者的进度、意见、决定、修回/校样任务 | 审稿人姓名/email、编辑私密报告/讨论、别人的稿件、未确认的决定草稿 |
| 审稿人 | 仅自己的邀请摘要；接受后该轮匿名文件与自己的报告/期限 | 未接受时全文、其他轮次/他人报告、作者身份（匿名策略禁止时）、真实文件名泄漏、编辑私密笔记 |
| 责任编辑 | 有当前分派的稿件及对应职责、候选/报告、可见文件 | 跨期刊/无分派对象、正式确认自己无权限的决定、把作者兼任角色当作无COI |
| 主编 | 本刊授予范围内分派/监督/决定材料 | 跨刊数据，作者本人稿件的自批，模型代为确认 |
| 出版人员 | 已进入制作并明确分派的接受版/制作包/校样任务 | 为制作而读取全部同行评审私密意见或自行改变编辑决定 |

权限在列表计数、详情、附件下载、搜索、history/引用、确认和模型context每条链路一致。审稿匿名文件必须经过负责人核对；只隐藏UI姓名或从正文移除`authors`数组并不足以匿名化文件内容和文件名。没有真实脱敏能力时只提供明确为无身份信息的合成匿名文本测试。

## 升级兼容与不变量测试

数据库/服务端至少需要以下有意义回归，不能用测试数量替代覆盖：

1. 从当前head升级，保留旧稿件UUID、消息/会话与已生成回执；第二次upgrade/启动不重复回填。旧screening标legacy且没有编造人类确认。
2. 准备稿可无责任编辑；作者未确认不能提交；提交冻结版本/作者顺序/文件hash，修改个人资料不改署名历史。
3. 版本/步骤/轮次/文件跨稿关联即使UUID真实存在也被DB复合FK或服务拒绝；当前指针不允许指向别稿版本。
4. 草稿编辑或换附件、重分派、政策版本变动后旧proposal确认409；确认内容/文件/收件人摘要必须逐项匹配，不靠客户端自报“已审核”。
5. 同一确认UUID并发（真实两个连接）只推进一次；重复同UUID不同payload409；失败中途回滚确认、任务、状态、审计/回执的一致关系。
6. 负责人变更后旧会话/旧Agent调用不能确认；同人兼作者主编拒绝自己稿件决定；普通编辑不能越过决定关口。
7. 邀请一人接受、一人拒绝时目标数正确；取消/过期不算有效报告；审稿人只见自己分派轮次和私密字段。
8. 作者/审稿人对详情、列表总数、文件、引用锚点、聊天history和模型工具不能借ID/搜索泄漏隐藏对象/身份。
9. 修回新版本不覆盖第一轮作者信息/报告/文件/确认；旧报告不被假装绑定新稿；新检查不能误写旧轮。
10. 邮件完整快照、修订撤销、数据库不可变性与send禁用不变量继续通过；即便环境开关true也无真实发送路径。
11. 录用/拒稿/制作预览必须负责人确认，Agent registry/API代理没有最终confirm能力；注入稿件内容不能请求SQL/shell/任意URL或更改角色。
12. 本地预览只显示确认快照，未授权访问403/404；内容变更使旧校样确认失效；没有外部部署/DOI/邮件动作。

## 浏览器完整样本的验收脚本应做什么

使用五组独立session/page，所有数据由实际UI/API写入PostgreSQL，禁止测试先塞一份最终状态fixture冒充用户操作：

1. 作者登录，创建准备稿，在常驻对话提供散乱合成信息；看到候选/来源和必需缺项。手动补充未勾选的声明、文件与作者顺序，刷新仍保留。
2. 打开独立审核材料，先修改使旧快照失效、再重新准备并确认；确认后拿到稳定编号、冻结v1、预审任务。
3. 编辑部登录，从左侧自己的真实优先事项进入同稿。分别记录完整性/人工相似度报告复核/材料匿名检查，每关人确认；右栏步骤事实随事务改变。
4. 主编在自己的任务中完成范围审核，指定责任编辑；责任编辑登录看到质量评估任务，确认送审，挑选已有合成审稿人并准备站内邀请。
5. 审稿人登录接受邀请、确认无冲突，仅看到分派匿名版本；填写作者可见与私密意见，独立审核提交。作者并行登录证明看不到私密字段与审稿人身份。
6. 责任编辑汇总建议；主编确认“修回”决定。作者看到已确认意见，提交v2和回复并确认；刷新可读旧v1与新v2，旧轮报告仍在。
7. 责任编辑复核/按首版规则完成后续必要关口，主编独立确认接受；AI只准备建议，不能替主编点确认。
8. 出版人员处理接受版制作包，作者核对校样，出版人员完成本地预览确认；打开需登录的可操作本地预览。不要命名为已正式对外发布。
9. 退出/重登，每个角色任务与当前步骤正确；核对DB版本/确认/任务/报告/审计；邮件捕获为0，外发禁用。原旧投稿/demo与邮件绑定回归不失效。

再做一条分支验收：审稿人拒绝或检查退回补交，任务与历史不丢、不可把流程自动当成功。对话在所有上述页面主体位置可见，移动/放大保留输入及材料，长审核表不挤掉对话；表单审核可以是新页面但共享layout中的同一对话组件不卸载。

## 可复用但需替换边界的实现

- `runtime.execute_command`的先查旧回执、事务锁、同事务审计模式可复用；不要把其仅编辑可用的固定作者create工具用在作者投稿。
- `editorial_chat.chat`的context digest、私有回合、失败不保存业务状态可复用；新DB上下文必须经对象授权，不能继续load_cases。
- `editorial_agent.check_actor`在模型等待后的role/journal/session复核值得保留；新增分派/COI/版本revision也必须提交前复核。
- `email_gateway`和数据库不可变approval触发器为负责人确认提供模式，但正式稿件确认和邮件批准应独立实体/能力。
- `editorial_demo`预期revision/冲突草稿保护可复用；每用户JSONB便利不等于可把共享出版阶段做成每用户不同状态。
