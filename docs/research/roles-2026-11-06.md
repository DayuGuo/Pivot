# 角色与多身份：OJS / Janeway 研究

研究日期：2026-11-06。本文件保留spec029实施前研究快照与建议；当前实现和验收以spec029及PROGRESS为准。委派任务：`role_research`；仅研究公开官方资料，隔离写入本文件，没有修改应用、访问业务数据或执行上游代码。

## 结论

同一个账号可以承担多个角色，但角色名称、期刊成员资格、稿件分派、本人任务、利益冲突及资料可见性必须分开。界面切换身份不能增加成员资格，也不能清除利益冲突。OJS 和 Janeway 均支持多角色；两者的管理员和编辑权限有配置差异，不能把其宽权限直接套给 Pivot。

保留 Pivot 的明确分工：作者提交自己的材料；审稿人接受邀请后处理固定匿名材料；编辑处理本人分派任务并提出建议；主编以实际任务独立决定。当前私人资料区仍仅限录入者本人，主编身份不授予他人的资料访问权。

## 安全切换的实现建议

下面是待实现/验收的建议，不属于上述已运行能力。

1. 界面显示当前期刊与当前工作身份；只有服务器返回实际可用的成员关系/角色才可选择。单身份只显示事实，不放无效切换入口。角色说明用上表短句即可，不堆叠第二层标签。
2. “切换身份”只选择本人已有的授权；角色授予、期刊加入、邀请接受须为不同的后端业务动作。请求传成员/角色的明确标识，服务器核对账号、期刊、有效期及 allowlist；不能接受任意 role 字符串并据此升级权限。
3. 活动身份成为服务端会话作用域的一部分。切换属于可审计的 Action Gateway 变更；轮换 CSRF/会话代次或等效机制，使此前页面的写入和确认不能在新身份下继续执行。长请求沿原身份复核，不能悄悄采用后来选择的新角色。
4. 切换提交后先隐藏旧资料，再重新获取任务、会话、稿件投影和允许动作。聊天、检索结果、原文、引用、下载、附件、表单、未上传文件和确认快照均按用户/期刊/角色/会话作用域隔离；不把旧编辑上下文带到审稿人或作者视图。迟到响应不得恢复旧材料。
5. 作者自审、历史署名冲突、已撤销分派及未接受审稿邀请，在所有身份中继续拒绝。切换不会重置这些事实，也不会恢复过期提案或替代独立确认。
6. 最低验收应覆盖：跨刊拒绝、伪造身份拒绝、切换前写请求过期、长模型请求结束后重验、撤权与多页同步、迟到响应、匿名文件直链、作者历史署名冲突、未知写结果恢复及切换后草稿隔离。验证要覆盖服务端策略和浏览器状态，不能只测下拉框显示。
