## 2. 核心建模原则

一篇稿件至少有五种不同事实：**现在在哪一步、正在看哪个版本、谁负责下一步、何时到期、有什么证据或缺项**。它们应有独立来源，界面可以合并展示，数据库不能合并成一个随意编辑的标签。

- `stage` 是确定性工作流状态；关键词、学科、稿件类型是分类；“缺作者机构”“可能未回应意见”是带来源的检查结果；“逾期”是期限与当前时间的计算结果。后三者不能自动变成录用/拒稿决定。
- 稿件、版本、评审轮次不是同一个编号：一稿多版本；一轮绑定一个审阅版本及文件集；大修后通常进入新轮。每次复核须说明核对的是哪个版本。
- 账号与作者署名分开：共同作者未注册也可被署名；邮箱/ORCID相同只提供关联线索，不自动授予访问权。作者信息随版本冻结。
- 业务关系用外键和显式字段；JSON 用于带 schema_version 的表单、作者原文信息及不可变证据快照。不在 JSON 里偷偷存第二套权限或当前状态。
- 私人资料包 `Dossier` 与正式投稿 `Manuscript` 分离。导入一篇公开论文不等于作者投稿、签署声明或授权出版。将来互转须显式确认、建立来源映射，不能直接批量改类型。

| 人类确认、回执与审计 P0 | 提案完整快照/摘要/版本/到期；确认人/时间；幂等请求与输入摘要；审计动作/目标/结果 | `ActionProposal/HumanConfirmation/ActionReceipt/AuditEvent` 和资料核对已有 | 日常仅显示执行结果和确认入口；完整审计在有权限的详情/管理视图，不能只记录聊天文字 |
| 邮件连接、草稿与发送 P0/P2 | 期刊邮箱、提供商、凭据引用、验证状态；逐封收件人/正文/附件快照与审批；将来 outbox、尝试和不明发送结果 | `MailAccount/EmailDraft/EmailApproval` 已有基础；凭据环境管理；无真实发送能力和完整生产投递队列 | 连接放设置，某稿邮件草稿/审批留稿件详情；保持禁发，不能把邮箱验证成功当允许发送 |
| 制作、校样与出版 P2 | 录用版、制作输入/输出、校样轮次、作者校样意见；期次、出版版本、DOI、许可、公开时间、勘误/撤稿关系 | `ProofPackage/ProofResponse/PublicationPreview` 到鉴权本地预览；无完整 Issue/公开Publication/DOI注册与撤稿生命周期 | 制作任务留个人工作区；期次/DOI/许可默认值进设置；具体排期/正式发布必须在稿件审批中处理 |

补充边界：正式投稿 `article_type` 当前仅允许 `research_article`、语言仅 `zh/en`；自由关键词不是受控学科体系。单刊试用先沿用，新增文章类型/多语摘要应由真实刊规驱动。出版社级 Press/Publisher 与跨刊成员授权待多刊切片再建立，不为单刊试用创建空壳机构层。将来接入OJS/Janeway还需保存 `external_system/external_journal_id/external_submission_id/external_version_id` 和同步来源/时间/冲突结果；这些是计划中的适配映射，不以导入时的新UUID冒充上游原身份，不立即做双向同步。

### 作者元数据的最低要求

“保存材料”和“确认完整资料”不是一个门槛。缺项允许先保存、标注来源和未核对状态，正式提交/资料确认再按本刊政策验证。

| 信息 | 现阶段原则 | 后续扩展 |
| --- | --- | --- |
| 姓名、署名顺序、机构、通讯关系 | 逐人保存，保留原文依据；不按名字猜机构，不因共享邮箱合并作者 | 单位名称＋ROR、部门、国家/地区的结构化快照 |
| 邮箱 | 私人资料可保留其他作者缺邮箱，完整核对要求通讯邮箱；正式投稿当前要求每位作者有效邮箱，不让 AI 填造 | 邮箱验证事件与账号登录关联分开 |
| ORCID | 可选；区分作者手填、原文提取、经本人授权认证；目前只有前两类线索 | 单独 ExternalIdentity/verification 记录；认证后也不自动授予稿件编辑权限 |
| 贡献、资助、伦理、数据可得性 | 录入实际提供的内容；根据学科/刊规决定必填，不强迫每篇论文捏造伦理编号 | CRediT、资助机构/项目号、数据 DOI/仓库、注册号；保留不适用和原因 |
| 改名、顺序调整、增删作者 | 新版本保留旧快照和原因；不能修改历史已确认版 | 作者变更专项审批及各方同意，不等同日常拼写修正 |

正式投稿与私人资料完整确认的“至多/恰好一名通讯作者”是 MVP 限制，不是科研通则。支持共同通讯作者前，应同时调整数据唯一约束、DTO、必填规则、表单、导出、人工快照及回归；不得只把复选框改成多选。

## 4. 流程与责任人

下面是 Pivot 建议的默认流程，不是 OJS/Janeway 对所有期刊强制的步骤顺序。今后刊规可允许某些检查并行，但必须分别保存检查证据和放行结果。

| 过程 | 主要责任人 | 输出与人工关口 |
| --- | --- | --- |
| 准备投稿、补资料 | 作者；编辑可辅助整理 | 版本、署名、文件、声明；作者确认投稿 |
| 完整性预审、相似度报告复核、技术初筛 | 分派的编辑助理/预审编辑 | 各项 CheckRun，负责人分别通过或退补；相似度不是自动抄袭判定 |
| 受稿范围与编辑分派 | 分派主编 | 范围记录、处理编辑；主编确认 |
| 文稿质量与是否送审 | 责任编辑 | 质量检查、送审准备或决定建议；退稿仍到有权限的决定负责人 |
| 寻找审稿人、组织评审 | 责任编辑；审稿人本人接受/拒绝 | 固定轮次/匿名材料/邀请/期限；邀请邮件另审，当前不发 |
| 完成审稿 | 审稿人 | 本人报告、建议、利益冲突声明；本人确认提交 |
| 编辑汇总、决定 | 责任编辑建议；主编决定 | 固定版本/轮次依据、匿名作者反馈；主编独立确认 |
| 修回与复核 | 作者修回；编辑逐点核对；需要时重邀审稿 | 回复信、新版本、每条意见的证据与人工判断；作者提交与编辑放行分开 |
| 文字编辑、制作和校样 | 制作人员、作者 | 排版文件、校样包、校样反馈；当前仅到鉴权本地预览 |
| 正式发表、勘误、撤稿 | 指定出版负责人＋学术决定负责人 | 另立审批与公开版本记录；当前未开放 |

## 5. 角色权限与功能表

以下为 **Pivot 目标权限**，不是上游默认权限的直接翻译。“本人/受派/本刊”是强制数据范围；一个人兼任多个身份不表示一次会话合并所有权限。

| 角色 | 可以看什么 | 可以做什么 | 不能做什么 / 人工确认 | 默认左侧工作 |
| --- | --- | --- | --- | --- |
| 作者 | 本人投稿、本人版本、明确公开给作者的意见/决定/校样 | 准备元数据、上传、回复、修回、核对校样 | 不能看审稿人身份或编辑私密意见；不能自审、自录用；本人确认投稿/修回/声明 | 待补资料、待修回、待校样 |
| 审稿人 | 本人邀请；接受且授权有效后看本轮指定匿名材料与获准分享的反馈 | 接受/拒绝、利益冲突声明、写报告、查看自己的报告 | 不能读作者联系方式或未授权历史材料，不能改稿/分派/正式决定；本人确认报告 | 待回复邀请、待交报告、到期审稿 |
| 预审编辑/编辑助理 | 受派稿件与预审所需文件、作者资料 | 核对完整性、查重报告人工复核、技术筛选、准备退补 | 不作正式录用/拒稿，不自动发送退补邮件；本人确认检查结果 | 待预审、待补资料复查 |
| 责任编辑 | 受派稿件、该稿评审与修回资料、自己的私人资料 | 质量初筛、选审稿人、准备轮次/邀请、汇总报告、准备决定建议、修回比对 | 不能读取其他编辑私人资料，不能代审稿人提交，不能以建议代最终决定 | 待送审、待邀审、评审催办草稿、待修回核对 |
| 主编 | 本刊已提交正式稿件；自己的私人资料 | 范围初筛、分派编辑、监督进度、查看建议并作最终决定 | 不能读取作者未提交草稿或他人私人资料；不能自审；最终操作仍需本稿任务/版本/回避检查 | 待分派、待决定、受阻稿件 |
| 制作/出版编辑 | 受派稿件的录用版、批准元数据、制作/校样文件 | 文字编辑、排版、发起站内校样、准备发布材料 | 不自动取得全部匿名评审材料或学术决定权；发布另审 | 待制作、待作者校样、待发布审批 |
| 期刊管理员（计划） | 本刊配置、成员职务、工作量及必要管理日志 | 设置刊规、模板、默认期限、人员授权及连接配置 | 管理权限不等于学术决定权或私人全文访问权；权限变更需明确确认审计 | 设置中的期刊/人员管理，不占对话主屏 |
| 部署管理员（运维） | 服务健康、备份任务、最少必要运维日志 | 安装、备份、恢复演练、安全密钥配置、授权范围内账号生命周期 | 不以普通 UI 权限读取保密稿件或作出版决定；基础设施特权实际可达数据库，须组织制度与专业审计约束 | 服务器命令；后续可提供受控运维页 |
| AI 助手 | 当前身份与对象策略允许传给模型的材料 | 检索原文、提取候选、起草、提醒缺项、准备白名单动作 | 不认证作者、不签声明、不授权角色、不确认稿件、不发邮件、不作最终决定 | 中间对话，建议附证据与待核对状态 |

**当前实现与目标的差异：**

- 已实现角色码为 `author/reviewer/editor/chief_editor/production_editor`。预审编辑与责任编辑目前共用 `editor`，由 `precheck/handling_editor` 分派职能区分；尚无独立“期刊管理员”业务角色。
- 当前邮箱绑定/验证允许 `editor/chief_editor`；模型配置只读，密钥由服务器管理。未来拆分期刊管理员时再迁移配置权限，本轮不静默撤权或新增授权。
- 主编对本刊已提交正式稿件有监督读取能力，但最终动作仍要求具体负责人任务。作者所有权仍可在其他活动职务下保持；身份视图筛选不能代替权限。自审冲突不得通过切换角色绕过。
- 私人资料仅录入者 editor/chief_editor 可见，同刊成员或主编也不能读取别人的资料。多位编辑共享需要单独的授权记录，不能仅去掉 owner 条件。
- 同刊多职务切换已实现；跨刊审稿邀请聚合、邮箱注册/验证、ORCID登录尚未实现。跨刊收件箱将来逐刊检查本人邀请权限，不创建“出版社全部稿件可读”的角色。
- 当前回避涵盖本人/历史作者账号或邮箱匹配及邀请利益冲突声明；不能声称完整识别合作、同机构、亲属等学术利益冲突。

邮件权限单独设计：未来审稿邀请/催办由本稿受派编辑逐封批准，决定通知须先有主编确认的决定，再由获授该稿通知权限的负责人逐封批准；制作通知由受派制作负责人核对。审批绑定收件人、完整正文、附件及不可变摘要，修改即失效。邮箱配置权不等于发送审批权，AI、作者或审稿人不能借对话取得编辑部外发权限。以上是未来放行规则；当前所有真实邮件仍禁发，不能从角色表推断已实现邮件投递。

## 6. 工作台与设置核对

### 主界面只回答三个问题

左侧：**我现在要处理什么？** 中间：**我想请 AI 帮什么忙？** 右侧：**这篇稿件处于什么状态，依据是什么？**

| 内容 | 建议位置 | 当前核对与处理 |
| --- | --- | --- |
| 全局搜索、个人待办、下方日历 | 左侧 | 已有统一搜索/正式任务日历；不再增加第二个对话搜索框 |
| 身份切换 | 左下头像/用户名附近 | 已有，保留；只列已授权身份，切换重读范围 |
| 当前稿件/主对话、连续消息、输入框 | 中央主体 | 已有不同工作区对话；跨入口统一是后续任务，不能直接混合不同权限的历史 |
| 下一步建议 | 输入框上方的小区域 | 按可用任务给少量建议，进入输入草稿或准备动作；“确认录用”等不得成为自动执行快捷指令 |
| 进度、当前版、负责人、期限、阻塞 | 右侧摘要 | 正式稿件有阶段/任务；私人资料只显示资料版本与核对状态，不冒充评审进度。后续统一成紧凑的只读摘要 |
| 作者详情、全文、检查报告、修回对照、工具记录 | 右侧按需展开/详情页 | 已有资料和核对面板；不把每个数据库实体变成主导航或常驻卡片 |
| 长表单、投稿/修回/决定/校样确认 | 独立任务页，仍保留可用对话 | 保留版本绑定和独立人工确认；这些是业务工作，不能移到“设置”藏起来 |
| 模型服务商/API/配置状态、邮箱连接 | 设置 | 已集中；没有浏览器密钥输入。设置不做隐式真实模型请求或发信 |
| 浅色/深色/跟随系统 | 设置 → 外观 | 本轮将 `/publishing`、`/workbench` 原侧栏选择器移入设置，沿用原存储范围；`/`、`/library` 原无该主题能力，不加假开关 |
| 阅读字号、段落定位 | 原文阅读工具条 | 保留近处：阅读时经常调整，属于当前材料操作；全局默认字号以后再入个人设置 |
| 稿件类型、必填项、默认审稿周期、表单/邮件模板、匿名政策 | 设置 → 期刊/流程（计划） | 当前没有完整可编辑设置；不为清单画无法保存的占位按钮。修改模板不能追溯改变历史快照 |
| 成员与角色、邮箱授权、模型可发送材料范围 | 设置 → 人员/连接/隐私（计划） | 分权并审计；不可默认让普通编辑看到或编辑全部管理选项 |
| 具体稿件改期、分派、邮件审批、决定 | 稿件任务/独立审批 | 与期刊默认设置不同，继续绑定这篇稿件和具体负责人 |
| 备份、恢复、更新及运行健康 | 管理/运维 | 当前保留现有安全命令；不在普通稿件主屏显示安装说明或内部版本计数 |

不为“简洁”删除必要事实：模拟模型、未确认版本、证据不足、过期依据、权限失败、未保存草稿和邮件禁发仍须在相关操作附近可见。邮件连接说明不必在每条对话重复。

### 本轮 UI 验收要求

外观面板打开不跳路由、不清空输入/文件；改变主题即时更新工作区和设置；关闭/刷新后沿用已有偏好；系统主题响应系统变化；手机设置分类不溢出；键盘切换分类及 Escape 可用。新入口不产生业务 POST、不改变权限和邮件状态。模型/邮箱已有授权与未保存保护不变。

## 7. 下一阶段的最小实施顺序

1. **先验证试用价值**：继续已有两位编辑任务包，记录真实导入遗漏、作者错配、证据不支持、复核用时。不能以测试数量替代这些结果。
2. **补元数据规范**：优先机构/贡献/声明的来源、未知原因及人工核对；按实际试用刊需求再支持共同通讯、结构化机构和数据可得性。先定义兼容输入与快照协议，再迁移，不改旧批准指纹。
3. **统一右侧摘要**：从既有数据只读投影当前版、当前步骤、负责人、真实期限及阻塞。私人资料只投影核对状态；不新增第二套状态事实或虚构 deadline。
4. **少量真实协作**：若编辑试用确实需要，先做显式资料共享/转交及撤权，不一次开放全刊私人资料。然后再设计通用成员管理、期刊政策设置。
5. **正式流程前的专业复核**：工程师审核租户/对象权限、盲审泄露、身份切换、重复确认、并发失效、文件解析/CAS、秘密配置、备份恢复和 2.5GB 容量；编辑部确认角色与实际刊规。真实供应商外发材料还需明确数据处理授权。
6. **后续出版模块**：期次、DOI登记、许可、正式公开版本、勘误/撤稿及邮件投递队列，独立规划和人工关口；本轮不实施、不部署。

需要的数据库约束随实际切片增加：同刊/同稿复合外键、稿件编号与版号唯一、有效分派去重、轮次/文件/确认一致、UTC带时区期限、按受派人/状态/到期时间索引、追加式证据、幂等键和并发 revision。不能为追求表格“齐全”提前创建几十张空表。
