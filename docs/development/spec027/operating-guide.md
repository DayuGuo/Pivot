# 单刊辅助核对操作指南

本轮面向指定编辑处理许可明确的非保密材料，不替代原投稿系统。实际验收状态和源码身份见[交付记录](review.md)及[PROGRESS](../../../PROGRESS.md)。公开静态站、既有VPS安装版和本分支候选包是三个不同版本；本轮不更新VPS。

## 启动与访问

本机执行 `./scripts/start.sh`，打开 `http://localhost:3100/library`。本地合成账号为 `editor@publishing.test` / `EditorDemo2026!`，只供本地；私人VPS包使用初始化时配置的私人账号，不能使用公开演示密码。启动器保留本项目既有真实模型环境，不修改Codex主模型或全局配置。

资料仅对录入它的当前有效编辑/主编开放，同刊其他编辑或主编没有默认访问权。试用管理范围建议一本期刊、2—5名指定编辑、10—30篇分批材料，尚未测得相应容量或共同编辑权限。

候选amd64离线归档来自[原生CI 42110416671](https://github.com/DayuGuo/Pivot/actions/runs/42110416671)，artifact名`pivot-private-app-linux-amd64`，源3307df6；不是新Release或已经部署的VPS版本。包及摘要可在本机`artifacts/spec027/amd64-final-ci/`找到，精确SHA见results。安装/保留数据升级与新项目恢复步骤沿用[私人包说明](../../../infrastructure/vps/README.md)和[升级指南](../../deployment/private-preview-upgrade.md)。

以后获准更新VPS时，先在新目录校验并解包，保留旧包、静态站及原私密state目录；在新包目录执行`python3.11 manage.py update --state /原有私密状态目录的绝对路径`，不要重新init或删除卷。update先备份DB＋CAS再增量启动，恢复演练只到新项目/新卷。本轮仅在隔离CI实际执行旧preview.4升级及新卷恢复，没有执行此VPS命令。

## 任务A：录入、核对与导出

1. 选择“新建资料”，填写题名、来源及授权说明，显式勾选材料授权后创建。只接受合成或明确授权的公开材料；不要用内部保密投稿测试。
2. 选择“导入 PDF / Word”，上传文字型PDF或`.docx`。原件≤5MiB、PDF≤60页、提取文字≤1MiB；旧`.doc`、扫描/加密稿及不支持结构会明确失败。上传和模型提取不改变当前版本。
3. 在独立页面切换“核对表单”“提取全文”“识别依据”，对照原件检查全文、作者顺序及机构/邮箱/通讯关系。Word使用提取段编号，不编造页码；格式或ORCID检查不是身份认证。图表、公式及阅读顺序要以原件为准。
4. 默认保留已有人工字段，即使这些字段是在第一次上传前填写的。展开“比较已保存字段与识别候选”，只有显式选择“使用本次识别结果”才替换；切换后尚未保存的修改需要再次确认。候选不等于核实事实。
5. 作者、摘要或关键词暂缺时，勾选“先保存材料，作者及其他缺项稍后补齐”，本人核对后选择“保存材料并继续审阅”。这会保存不可变新版本和原件来源，但不生成完整资料核对记录。缺项继续显示，不妨碍询问与缺项无关的正文事实。
6. 资料齐全时可走完整核对并保存；之后修改仍产生新版本，旧核对不自动移交。类型、资助及声明原文的候选也须对照来源；录入原文不等于作者签署原创性、版权、伦理或利益冲突声明。
7. 回到资料区，在中心对话询问当前版本，点击引文核对确切文件、版本和位置。显示“模拟”时没有真实模型推理；真实调用失败不会伪装为模拟成功。元数据模型仅读取开头14,000字符，后文资助/声明可能需要手动补录，问答显示实际材料覆盖，不能由有引文推出科学正确性。
8. 选择“导出资料与缺项”，下载精确版本JSON，包含元数据、缺项、作者冲突、原件身份、可证明的字段来源和核对状态。它不含完整正文、私人问答或服务器存储路径。手填但无法证明来自原件的值不伪造来源。

外部引用当前只核验资料/问题明确给出的DOI与Crossref书目记录，未检索或读过外部全文；不把书目匹配说成结论已被外部研究证实。

## 任务B：内部修回核对

1. 在同一资料下先保存原稿，再导入并核对修订稿。两个版本都是真实保存的材料；文件同名不会覆盖历史原件。资料版本不是评审轮次，也不自动成为正式投稿。
2. 在资料栏选择“修回核对”，选较早原稿与当前修订版。将意见预拆成1—8条可核对要求，每条保留完整原意见上下文；当前不是可靠的自动复合意见拆解。
3. 粘贴作者回复及来源说明，如实标记原稿、修订稿、意见集合和回复是否完整。没有拿到全文或完整回复时不要勾选完整。当前支持原/修订PDF/DOCX，意见与回复是来源明确的粘贴文本，不是四份文件自动识别关联。
4. 勾选材料授权，选择“生成修回核对”。系统使用有限预算的只读比较和独立上下文支持检查；成功保存核对包，失败不产生半个成功包。Mock不冒称完成语义判断。
5. 打开“查看原稿”“查看修订稿”和逐条“定位…原文”，分别核对作者如何回应、正文是否有相关修改、证据是否足以处理要求。未定位不等于证明全文未修改；合理不采纳可以是已回应且未修改。
6. 人工分别选择回应、正文落实、编辑处理意见，写明理由；本人勾选核对后“保存人工判断”。三层选择互不替代，可以记录“有理由不修改，编辑认为无需进一步处理”。记录只属于这个核对包，不执行录用、拒稿或正式修回。
7. “人工判断历史”保存追加记录；重新读包更新并发前置记录，保留未保存草稿但要求重新核对。旧包可以追加判断，界面明确历史材料；不得借旧包确认新版本。
8. “导出修回核对 JSON”包含包、两版来源、回复与最新人判，故包含全文和作者资料，仅限获授权使用。平台不能撤回已经合法下载的外部副本。

## 失败和中断

| 情况 | 操作与保证 |
| --- | --- |
| 上传/模型忙，HTTP429 | 等待提示时间后主动重试；不自动无限排队 |
| 模型超时、协议或引用不合法 | 明确失败，不保存半个回答/核对包；不要把失败当“材料没有问题” |
| 写请求结果未知 | 保留原输入和请求UUID，主动恢复；不要另开相同提交制造第二个业务请求 |
| 已知保存成功，但后续读取失败 | “恢复已生成核对包”或“恢复已保存判断”仅读取；恢复已保存判断无需重新签署 |
| 其他标签先保存，HTTP409 | “重新读取核对包”，对照最新判断；保留草稿，重新勾选后再提交 |
| 换稿、换账号、撤权或注销 | 旧响应不恢复私密界面；后端重新检查权限，旧链接不授予访问权 |
| 需要继续补元数据或正文 | 保存新版本；旧回答/核对/引文继续绑定旧版本，不自动重基 |

EMAIL_SEND_ENABLED始终为false；邮件和关键出版决定仍由有权负责人另行核对，模型没有确认或发送工具。
