# 正式出版工作台角色走查

2026-11-18。使用独立 Mock 栈和 `.test` 合成账号。Computer Use 的浏览器控制服务无法连接，实际浏览器操作由 Playwright 执行。走查从登录表单进入正式出版工作台，并检查待办、对话和设置。

| 角色 | 检查内容 |
| --- | --- |
| 作者 | 我的投稿、新建入口、取消离开后的原题名和请求数、新建请求等待时的追加编辑 |
| 审稿人 | 本人审稿邀请、列表载入状态、390px 工作列表的键盘操作 |
| 编辑 | 受派稿件、个人资料入口、期刊邮箱设置入口 |
| 主编 | 期刊稿件、个人资料入口、期刊邮箱设置入口 |
| 制作编辑 | 本人制作任务和账号设置 |

五个身份均检查打开和关闭设置后，对话输入保留。身份切换、匿名审稿、修回、校样、鉴权预览使用已有合成流程回归。

| 发现 | 修复 |
| --- | --- |
| 工作列表盖住稿件和对话时，键盘焦点仍可进入背景，Escape 无法关闭 | 正式工作台复用资料区的抽屉逻辑。打开后聚焦关闭键，Tab 留在列表内，设置接管焦点，关闭恢复入口。视口变宽或从日历打开稿件时自动关闭 |
| 作者取消从未保存的稿件离开，仍创建了一条空稿 | 创建前确认，取消时请求数为零。创建失败时保留原编辑保护，等待期间的新编辑需要重新确认离开 |
| 重复点选同一稿件时仍要求确认离开 | 同一路径和稿件只收起抽屉，继续保留草稿保护 |
| 工作列表读取中出现空状态，审稿及制作空对话出现作者专用提示 | 在收到工作列表后显示真实空状态，对话提示改为可用于各角色的简短指引 |

首轮 Chromium 中五个角色入口场景通过，两项专项复现了窄屏焦点与空稿问题。后续专项发现测试的角色定位器不能判断原生 inert，并且窄屏使用独立日期输入。修正验证方法，再分别检查实际 Tab 循环、inert 和手机日期输入。最终十个场景在 Chromium、Firefox、WebKit 各通过一次，共 30 项。完整 `scripts/verify.sh` 退出 0，后端 1,784 项，三浏览器 618 项（各 206），静态检查、迁移无漂移及生产镜像构建通过。原始日志与源码摘要保存在 `artifacts/role-walkthrough`。当前结果覆盖 Playwright 的仿真窄屏和 Linux WebKit。详见 [PROGRESS](../../PROGRESS.md)。

代码复核另外发现，已过回应截止时间的审稿邀请仍可能显示“等待回应”。这项涉及服务器期限与迟到拒绝的现有差异，留待用真实轮次单独复现。正式投稿的本地文件取消选择也值得独立验证。两项均没有在本轮改变。
