# 本人日历交付记录

当前范围见[spec031](../../specs/031-personal-deadline-calendar.md)，[官方研究](../research/deadlines-2026-11-06.md)与[结构化结果](personal-calendar-results.json)。实现与完整验证进行中，不借此前搜索测试声明完成。

## 使用与边界

四个已登录工作区左下角展开“日历”，选择月份或具体日期查看本人当前职务的正式稿件截止任务；“逾期”包括以前月份，“今天”按显示时区定位。桌面日期格支持方向键与Enter，窄屏/触摸用原生日期选择。点击任务进入对应稿件，中央对话仍在，原未保存确认保留。

所有条目来自已有持久WorkItem及确定性职责投影，不是模型生成。邀请回应/报告、正式修回、编辑/主编/制作任务沿已确认流程的截止记录；未设日期明确计数，不填假日期。作者需切换到作者职责查看自己的草稿/修回/校样；其他职责不自动兼任。旧legacy记录没有规范化日期，不补造历史。当前没有改期、提醒、邮件、外部日历同步或跨期刊汇总。

时间按浏览器IANA时区解释，页脚显示该时区；部署不识别时提供“使用 UTC”的明确选择。“重新载入”处理网络/正文超时；分页位置无效时从首批恢复。会话失效清除私人结果，重新展开不自动重发旧权限请求。正式工作区的真实待办更新会刷新展开日历并保留月份/日期；其他入口重新展开或切换筛选读取最新，不宣称服务器实时推送。

## 模块与验证

metadata_access与calendar_queries只构造SQL，不执行写入/HTTP/模型；calendar路由负责时间区间、游标和会话复核，components/calendar统一四入口。独立模块边界脚本纳入禁止路由/传输/执行写入；没有数据库迁移。查询按授权与筛选后限额，不从最近200篇浏览窗口过滤。

已执行日历/搜索专项53项（最终SQL拆分后37.27秒）通过；首轮Chromium8项13秒通过。增加四工作区展开布局断言后，三引擎专项120过/3失败，定位为原主工作台顶部导航占用较多；按各工作区空间分配修复，未降低断言。另在旧镜像实际红测分页422、未支持时区及响应头后正文停住三个恢复问题及真实职责变化后的旧日历滞留，失败trace保留在忽略的artifacts/calendar。两个API夹具违反数据库保护时改为合法构造，保护与断言未放宽。

深色截图等待样式过渡与字体/对话实际载入，不把半加载画面当最终证据。日历目标的单次设计检测为[]，不代替浏览器与独立视觉复核。通用fresh审查Agent按Impeccable要求查看十张图后给出fix：主工作台月历只显示前两周；已重新分配次要导航空间，并新增末周/筛选与身份同时可见的断言，同一审查者已查看全部十张重拍并判定该P2 resolved、限定ship；未独立执行测试，不认证后端、真机或读屏器。三引擎全部日历修复回归与完整verify结果以结构化结果和PROGRESS的结束回执为准。Linux WebKit软件渲染不代表真实Safari/手机软键盘认证。
