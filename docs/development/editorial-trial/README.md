## 本轮可操作增量

- 部署负责人开通独立editor账号、停用、恢复或轮换密码；不共用owner账号。
- 停用撤销所有登录会话，同时保留资料、版本、原件、核对与审计。恢复后需要新密码重新登录。
- 私人版编辑登录直接进入资料区；从具体资料返回登录后仍回到同一资料。
- 每位编辑只看自己的内部材料，不默认共享另一编辑的工作；有意比较同一论文时各自导入公开副本。

这不是邮件注册或身份认证服务。命令需要持有该私人安装的服务器管理权限及已有安全state，不能从浏览器或模型调用。

## 负责人操作（安装包含本片的新包后）

目前没有发布本片安装包，也没有更新VPS。以下命令是新包的操作协议，不能假定旧包已支持。先按[保留数据升级流程](../../deployment/private-preview-upgrade.md)另行完成获授权更新；不要重新init、删除卷或覆盖旧state。

在安装包目录使用现有state：

```bash
python3.11 manage.py trial-list --state /绝对路径/既有私密state
python3.11 manage.py trial-create --state /绝对路径/既有私密state --journal 期刊UUID
python3.11 manage.py trial-disable --state /绝对路径/既有私密state --journal 期刊UUID --user 用户UUID --revision 当前修订号
python3.11 manage.py trial-resume --state /绝对路径/既有私密state --journal 期刊UUID --user 用户UUID --revision 当前修订号
python3.11 manage.py trial-rotate-password --state /绝对路径/既有私密state --journal 期刊UUID --user 用户UUID --revision 当前修订号
```

list给出期刊ID、托管名单和当前修订号。create询问邮箱/显示名/无回显密码，其余操作按目标ID执行；变更前必须输入CONFIRM。账号仅editor，密码不显示、不保存到state、不放进命令行。终端不能关闭回显时命令直接停止；远程运行需分配安全TTY，不能退回管道输入密码。负责人先获得参与者同意，并用双方认可的安全方式交付凭据；系统不会发通知邮件。

每次变更先打印非敏感request ID。网络断开或结果未知时先trial-list；必要时用原`--request-id UUID`及相同输入重试。已被后来修改取代的回执会拒绝，不恢复旧密码或旧状态。错误不打印秘密，服务端审计记录实际操作及revision。名单最多10个，包括停用账号；账号owner交接、多期刊和角色变化不在此命令内。

## 编辑30分钟首次操作

1. 用本人账号打开`/library`，新建资料并确认材料授权。选择[已有许可材料索引](../../../evals/single_journal_pilot/README.md)，不上传保密投稿。
2. 导入一份文字PDF或DOCX，在独立核对页对照原件，检查作者顺序、机构、通讯关系、摘要和全文。先保存不完整材料也必须本人核对，不把缺项当已确认。
3. 问“按原文列出作者和机构，指出哪些关联不能确定”“主要结论受到哪些限制，请提供原文”。逐条点击引用，核对版本、页/段、上下文；Mock标签表示未做真实语义推理。
4. 对一个有问题的结果记录人工判断和原因，导出资料及缺项。刷新验证保存存在。未经原文支持的结论不应直接采用。
5. 记下从导入到查证、纠错、导出的总时间，包括失败和等待，填写实际是否愿意继续用及原因。用原工作方式处理另一份难度相近材料作探索比较；不要同篇先读后测再声称提效。

详细路径见[既有操作指南](../spec027/operating-guide.md)。新本地验证入口是http://127.0.0.1:13100/?entry=library，仅隔离Mock演示账号；它不是私人账号或VPS地址。
