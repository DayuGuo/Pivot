# 下一步：修回对照的实际评价

当前证据是合成正式工作流、恶意/不完整引文回归及真实DeepSeek合成工具协议。没有宣称真实论文修回准确率或专家核验。本计划不把待采集样本计为已执行结果。

## 成熟系统经验与本轮对应

依据已固定源码和来源的[OJS工作流研究](../research/library/ojs/workflow-and-policy.md)及[Janeway字段索引](../research/library/janeway/README.md)：稿件稳定身份、版本、评审轮次、实际分派、作者可见意见、修回要求与决定应分离。本轮来源服务复用已有正式实体，只读当前有权版本和实际已向作者释放的要求；不能把角色名称、作者声称上传、编辑私密意见或AI判断直接当成业务完成。没有复制或运行上游AGPL源码。

OJS对“修订上传”和“新评审轮”归属的提醒尤其适合后续PDF/Word衔接：经人工确认的解析全文应与原件及具体正式修回版本绑定，不能只凭相同题名或最近上传时间推断。同一篇稿件的私人资料记录也不能自动取得正式稿件或其他期刊的权限。

## 样本与权限

先选2组明确获许可的原稿、修订稿、作者回复和对应作者可见意见，目标至少20条可独立核对要求。必须逐文件核对许可、来源和版本关系；论文开放许可不能自动视为作者回复或同行评审记录也开放。无可靠许可时继续使用明确合成样本。不得上传真实保密稿件。未收到文件前不编造来源链接、期刊或结果。

由获授权编辑逐条登记原要求、复合子要求、作者回应位置、实际修改位置、是否只改附件、解释未改是否需要进一步判断。两位核对者先各自评价，分歧由负责人记录；没有专业核对者时记录为产品内部测试，不冒称独立专家验收。

## 重点失败类别

- 作者说已修改，正文没变；只更换空白或无关句子；原样引文被误作新改动。
- 已回应但尚未落实；合理解释未改也不等于编辑已同意。
- 复合要求只回应一半；否定、比较组、时间条件、统计限定或附件被漏掉。
- 大修仍应重新送审；模型不能替代实际轮次与负责人决定。
- 超过8段/1200字符或窗口读取不完整时，被错误称为全文已核对。
- 重复引文、错版本、错文件、错轮次；权限变化、未提交草稿及旧回执恢复。
- 致谢/叙述被误判为待修要求；真实要求被模型逃避为“不适用”。

## 指标与放行

分别记录逐字定位正确率、假报修改完成、遗漏的复合子要求、已回应误报未回应、依据不足却给肯定结论、上下文截断与处理时延。优先人工检查所有“修改有证据”；已知坏例不得报修改完成。Mock和未完整读取的结果单列，不能充当语义准确率分母。小样本通过只允许扩大内部试验，不能推导普遍准确率或生产安全。

记录实际模型/工具阶段、Token、时间、供应商账单成本和返工；成本未知保持null。同步验证业务表不变、无自动确认、EMAIL_SEND_ENABLED=false、Mailpit无新增。正式受控试点前请专业后端/安全工程师复核授权、版本绑定、存储与恢复；编辑复核质量判断和作者可见性，不能由开发者或模型自证。
