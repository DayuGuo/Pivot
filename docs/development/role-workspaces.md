# 身份工作区交付记录

本轮实现见 [spec029](../../specs/029-role-workspaces.md)，官方依据见[研究](../research/roles-2026-11-06.md)。当前正在完成完整门禁；本文件的最终结论必须以实际结束回执更新，不能将下方专项通过当作全量完成。

## 使用

真实应用登录后，点击侧栏底部头像／姓名，选择已获授职务，在独立页确认，进入对应 `/publishing` 工作区。对话始终居中，待办和默认稿件列表按编辑／审稿人／主编／作者职责聚焦。单职务用户只显示自己的实际职务，不能自助获得其他权限。

本机合成多身份账号：`multi@publishing.test` / `MultiDemo2026!`，仅 local bootstrap 创建；私人部署不启用该密码、不扩权现有编辑账号。现有六个单身份账号仍保持原密码和职务。此轮不提供角色授权管理后台；现有真实账号需部署负责人另行配置授权，不能将展示账号用于生产。

## 模块

- `security.py` 管理唯一期刊解析、活动成员与原身份复核；`identities.py` 是只供人类 HTTP 的会话变更网关，复用业务请求锁和不含凭据的 ActionReceipt。
- `work_queue.py` 的可选职责视图与原对象策略分离；`core.assign` 精确选择目标职务，防止多行成员误配。
- `components/identity` 管理共享菜单、独立确认、只读恢复、跨标签页隔离及集中界面文案；四个真实工作区复用同一控件。`IdentityBoundary` 关闭已改变权限的旧私人页面，设置也随之卸载。
- 迁移只调整成员唯一键并增加明确会话成员外键。旧迁移及审稿、决定、私人资料数据库守卫保持不变。

## 范围限制

未进行实际云邮箱或专业外部安全复核；Linux Playwright WebKit 不等于真实 macOS/iOS Safari 硬件验收。多期刊、角色管理后台、外部注册和出版社范围邀请聚合仍为后续阶段。正式录用、拒稿、修回、报告提交与其他关键关口依然由实际负责人独立确认，EMAIL_SEND_ENABLED=false。

本轮不自动合并、更新 VPS、发布 Release 或改变公开静态站。现有主应用容器在本轮开始时已停止，不据此宣称新功能已部署到用户现有主端口。验证应用使用独立 Mock Compose 项目、端口和持久卷，不能与用户 VPS 运行状态混淆。
