# 多职务账号与身份工作区

日期：2026-11-06。基于 spec028；这是既有工作区的扩展，不替换对话中心布局，不将静态展示站当作权限系统。依据见[OJS / Janeway 研究](../docs/research/roles-2026-11-06.md)。实际执行证据统一记录于 PROGRESS 与[交付记录](../docs/development/role-workspaces.md)。

## 职责与界面

| 身份 | 默认工作区 | 权限与人工关口 |
| --- | --- | --- |
| 作者 | 我的投稿、本人待补资料／修回／校样任务 | 只处理本人材料与已明确分享的作者意见；投稿、修回与校样由本人独立确认 |
| 审稿人 | 我的审稿邀请、本人回应与报告任务 | 本人邀请；接受且授权有效后读取本轮固定匿名材料；本人声明并提交报告，不决定录用 |
| 编辑 | 待我处理的稿件、编辑待办、本人内部资料 | 按实际分派预审与处理；邀请和评审准备、结束轮次与建议仍走独立人类关口；不读他人的私人资料 |
| 主编 | 期刊已投稿件、本人分派与决定任务 | 同刊已提交正式稿件监督；最终确认仍需实际任务、版本与利益冲突检查；不访问他人的私人资料 |
| 出版编辑（保留） | 我的制作任务 | 录用正文、批准元数据与自己的校样任务；不获得正式公开发表权限 |

身份、实际任务和所有权是不同事实。所有成员原有的本人作者权保持兼容：切换工作视图不会剥夺本人稿件访问权。新增 `role_view=true` 仅让默认列表与待办聚焦当前职责，不能授予新的对象访问权；默认 API 投影与历史业务保持兼容。本人投稿即使在其他职务下仍须回避编辑、主编或审稿判断。主编看得到已投稿件不等于能代替每个负责人确认。

## 数据与服务端合同

- 一人可在同一期刊拥有多个 Membership，各行代表已授予的一个职务，唯一键为 `(user_id, journal_id, role)`。不自动向现有账号增加职务，也不提供自助提权 API。
- LoginSession 新增明确的 `active_membership_id`，复合外键绑定成员 ID 与本人用户 ID。迁移只回填恰有一个成员关系的旧会话；不猜测多期刊上下文。当前多期刊账号仍拒绝自动选择。
- `GET /api/auth/identities` 返回当前账号、期刊、活动身份、实际获授职务及 CSRF；不生成新授权。
- `POST /api/auth/identity` 必须通过现有 cookie、CSRF、同源及 allowlist，携带 UUID。通过统一认证变更网关，在一个事务中选择实际成员行、轮换 cookie 与 CSRF、撤销旧会话、记录安全回执和审计。切换不延长原登录有效期。回执不包含凭据；重复 UUID 不会在后来的不同身份下重新切换。
- 请求锁先于会话锁，与业务网关顺序相同；目标成员行新读取并加共享锁。业务最终提交短暂锁住原会话／成员，切换与已进行提交串行；网络和模型等待期间不持此锁。旧请求不沿用新身份。原有长请求的逐次权限复核继续生效。
- `29b6d4a01c75` 是增量迁移：不删业务行、不改旧审批或证据指纹，现有数据库触发器的精确角色检查继续适用。存在多职务时拒绝降级，不能通过降级丢弃授权。

## 交互与恢复

头像／姓名整体是原生身份菜单，展示实际当前职务和服务器返回的可用职务。选择后先离开原工作区，由已有未保存保护决定是否继续，再进入独立确认页；只有本人点击“切换为…”才改变会话。这样取消离开不会先改变权限。

切换成功以新文档进入 `/publishing`，重新加载任务、稿件投影、对话和允许动作。未知写结果不自动重发，必须主动读取当前身份；已经切换可直接进入，未切换才显式重新请求。当前身份不产生 POST。读取身份失败或不匹配不展示旧选项。

其他标签页收到跨页通知或重新聚焦／显示／BFCache 恢复时重新核对当前身份；已变化则移除旧私人页面与表单，要求进入新工作区。浏览器不支持 BroadcastChannel 时保留聚焦恢复。不能把前端隐藏当作授权，所有请求仍由后端核验。

沿用 DESIGN 的低饱和三栏与主对话；桌面、390px 深色、键盘与 Chromium / Firefox / WebKit 回归均需验证。真实邮件继续禁用，模型没有身份切换或最终确认工具。

## 本轮边界

只新增同刊多职务与实际工作区，不实现多刊选择、角色管理后台、注册／ORCID 认证或跨出版社邀请聚合。局部非保密演示账号 `multi@publishing.test` 初建时拥有四个职务；现有账号和私人部署账号不扩权。早期 `/` 的个人历史对话和 `/workbench` 合成编辑材料仍按账号保存，不宣称它们已经迁为完全独立的多职务正式工作区；正式 `/publishing` 对话既有角色作用域继续保留。

验收包含伪造／跨刊拒绝、旧 cookie/CSRF、并发切换与旧请求、补充审稿人真实匿名材料授权、作者回避、私人资料隔离、列表职责、未保存取消、回执丢失与跨页恢复，以及完整 `scripts/verify.sh`。
