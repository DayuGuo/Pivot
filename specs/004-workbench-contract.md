# Core editorial workbench implementation contract

Goal source: user-supplied goal-objective.md 2026-11-02. Scope is four interactive editorial pages, explicit synthetic dataset, necessary persistence; not full production workflow003. Read models/security and retain current real intake. Route `/workbench` reuses existing session. Editors/chief only; author/reviewer receive a clear403, no dataset leakage. No external sends, decisions, cancellations or permission changes enabled.

Shared frontend DTO: apps/web/components/editorial/types.ts. Backend fixture lives packages/editorial_demo/dataset.json (synthetic, no real people/citations; sources denote synthetic scenario locations). At least6 cases spanning screening, assignment, reviewers, review, decision and production; case `demo-001` richly covers bilingual long paper,3 versions,2 review rounds, figures/refs/attachments,3+ reviewers and long history.

API through current same-origin proxy:
- GET /api/editorial-demo -> Dataset `{demo:true,cases:Case[],states:Record<case_id,CaseState>,saved_views:ViewState[]}`. Pure read, no seed writes on GET; fixture static, user states default projection.
- PATCH /api/editorial-demo/cases/{id}/state body `{expected_revision:int,patch:Partial<CaseState without revision>}` -> full CaseState. Actor+journal scoped, optimistic lock409, validate key/IDs/status/outcome/limits; never merge arbitrary untrusted JSON. Store private drafts, synthetic issue verification, selected candidates, paragraph-level reading position and model result disposition. No canonical publishing status change. Save audited, secrets excluded. Agent cannot mark official decisions/sends/cancel tasks via patch.
- PUT /api/editorial-demo/views `{views:ViewState[]}` -> `{saved_views:ViewState[]}`; own user+journal scope, max12 views, validated filter/sort, persistent.
- GET /api/editorial-demo/cases/{id}/files/{attachment_id} -> original synthetic text attachment download with no path traversal. Original versions remain accessible from reader; anchors always include version/section/file/location. Reflowed article is fixture content, no claim of parsing uploaded confidential manuscripts.

Data adjustments minimal: isolated per-user+journal case workspace state table (JSONB typed allowlisted content + revision), own saved view state table. No migration of real publishing state. immutable fixture is independent data boundary replaceable with live service. Backend owns validation/permissions/audit. Current projection status/draft decisions not real outcomes. Judgments/results remain bound to immutable issue/version IDs; reading another version preserves them and filters visible scope. Content replacement requires a new version and re-verification; final official actions failclosed (no transport).

UI concept: Operate/Read extension of quiet neutral existing system. System UI font+Noto CJK fallback,14–15px controls,16–18px reading,1.7 lineheight. Background#f5f6f8, surface#fff, ink#242833, muted#5f6674, line#e1e4e9, indigo#4659c7. Consistent workbench-scoped dark variables. Left navigation and queues; center operational page; optional right preview/agent context. Reader body dominates and uses dedicated resizable side panel, TOC and focus mode. Source hierarchy: latestgoal references for task patterns, user Hermes screenshot for quiet chrome; no Notion aesthetics/multiple UI libraries.

Acceptance includes existing145+8 regression + meaningful new API tests and Playwright four-page chain, filter/view/scroll restoration, reading/evidence anchors, revision+draft persistence, no cancellation,403+CSRF+409, theme/system/font/keyboard/panel width, zoom200%, widths1366/1440/1920 screenshots; only actual Linux Chromium verified, otherOS/browsers documented untested.
