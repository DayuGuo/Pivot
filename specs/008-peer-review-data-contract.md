# D: fixed-round in-app peer review data contract

Implementation follows C; this file is a contract, not completion evidence. Consult both pinned systems and `docs/research/library/comparison/review-revision-design.md` before implementing. Main decision/revision/production entities are separate later increments, not empty tables in this migration. No real mail or bearer invitation links.

## Four new entities

Use existing Base/uid/now, String36 IDs, UTC timestamps and named constraints. Every new id/manuscript parent key has UNIQUE(id,manuscript_id), tenant via (manuscript_id,journal_id). Keep supplied column names stable so API, migration and tests agree.

**ReviewRound / publishing_review_rounds**: id, manuscript_id, journal_id, version_id, round_no, status(initializing|open|closed|cancelled), material_sealed_at nullable, required_reports1..3, policy_version, review_method='double_anonymous', form_key='basic_peer_review', form_version=1, form_snapshot JSONB, form_digest64, material_digest64, opened_by FKUser, opening_confirmation_id same-manuscript FK, closing_confirmation_id nullable same-manuscript FK, opened_at, closed_at nullable, closure_reason default empty. UNIQUE(manuscript_id,round_no), UNIQUE(id,manuscript_id,version_id), partial UNIQUE manuscript where open. Use initializing only within the atomic open transaction: insert Round then files, seal status=open with material_sealed_at after validating complete fixed material. A deferred constraint trigger must reject a committed initializing round. All material/form/policy/target/opening facts immutable after insert; only initializing→open followed by open→closed/cancelled with timestamp+nonempty reason; terminal cannot edit/delete. Insertion requires frozen same-manuscript version and correct open_review proposal/confirmation/preparer/responsible handling editor, never any unrelated author confirmation. Insert RoundFile rows within the same opening transaction, then round material set becomes immutable (gateway parent lock plus DB guard tied opening confirmation/current workflow state; no arbitrary later inserts). Cross-table immutability must survive concurrent writers.

**ReviewRoundFile / publishing_review_round_files**: id, manuscript_id, round_id, version_id, version_file_id, role='blinded_manuscript' (v0.1 D only), display_name (server generated anonymous review-manuscript.txt/md, not original upload name), created_at. UNIQUE(round_id,version_file_id), UNIQUE(id,manuscript_id). Triple FK(round_id,manuscript_id,version_id)→Round and (version_file_id,manuscript_id,version_id)→VersionFile; add parent UNIQUE(id,manuscript_id,version_id) to existing VersionFile. Actual link must purpose blinded_manuscript and visibility reviewer, frozen version; no full/manuscript private file. Rows cannot update/delete/truncate or append after opening lifecycle gate. Do not insert an always-closed guard that also blocks the legitimate atomic initial file set; provide a tested initialization boundary.

**ReviewInvitation / publishing_review_invitations**: id, manuscript_id, journal_id, round_id, version_id, reviewer_id FKUser, attempt_no>=1, status(pending|accepted|declined|cancelled|expired|submitted), invited_by FKUser, invitation_snapshot JSONB (typed anonymous scope/title/abstract/instructions, no author identity), content_digest64, policy_version, response_due_at, report_due_at, invited_at, responded_at nullable, accepted_at nullable, declined_at nullable, cancelled_at nullable, completed_at nullable, conflict_status(unanswered|none|declared), response_notes Text default empty, invitation_confirmation_id FK same-manuscript, response_confirmation_id nullable FK same-manuscript, terminal_confirmation_id nullable FK same-manuscript. UNIQUE(round_id,reviewer_id,attempt_no), active partial UNIQUE(round_id,reviewer_id) WHERE status IN(pending,accepted,submitted), UNIQUE(id,manuscript_id,version_id,reviewer_id). Round/manuscript/version triple FK. Opening/reviewer/content/deadlines immutable; transitions pending→accepted/declined/cancelled/expired, accepted→submitted/cancelled, terminal immutable. Pending→accepted requires explicit reviewer no-conflict response confirmation, no author COI and current reviewer membership; submitted requires own frozen report. Invitation confirmation must actually bind invite_reviewers/open_review payload target/round/version/user and opening actor. Cancellation references actual closing/cancel invitation human operation, never fake submitted timestamps. Expiration may be deterministic time-based with audit and no approval fabricated.

**ReviewReport / publishing_review_reports**: id, manuscript_id, invitation_id UNIQUE, status(draft|submitted|withdrawn), revision>=0, form_snapshot JSONB, form_digest64, author_text Text default empty, editor_private_text Text default empty, answers_json JSONB default {}, recommendation(unanswered|accept|minor_revision|major_revision|reject), created_at, updated_at, submitted_at nullable, human_confirmation_id nullable FK same-manuscript, content_digest nullable64. Round/version/reviewer derive from immutable Invitation; do not duplicate contradictory columns. Report insert requires accepted no-conflict invitation and grant; form snapshot/digest equals fixed Round form. Submitted requires exact submit_review human confirmation by invitation reviewer, snapshot/form/target binding and valid open round/grant. Submitted/withdrawn cannot edit/delete/truncate; draft metadata cannot switch invitation/form. Withdrawing is explicit cancellation, never fake submission. Required answers schema belongs deterministic backend, editor-private and author text are separate relational columns; only later chief-confirmed Release DTO grants author access.

## Existing relation extensions

**Assignment**: add nullable review_invitation_id same-manuscript FK; extend capability enum reviewer. CHECK(capability='reviewer') == (review_invitation_id IS NOT NULL). Reviewer grant user/version derived from invitation and only accepted/submitted active invite with acceptance confirmation; role reviewer/current journal/no COI. Existing author/precheck/editor/chief/production cannot carry invitation target. Replace old active unique(user,manuscript,capability) with partial same key for non-reviewer rows; reviewer active unique(invitation_id,user,capability) to preserve separate historical rounds. Grant ends at cancellation/close without changing creation provenance; no reactivation.

**WorkItem**: add nullable review_invitation_id and review_report_id same-manuscript FK, at most one non-null. Replace UNIQUE(step_run_id,kind,assignee_id) with partial equivalent where both typed targets null; add partial UNIQUE(invitation_id,kind,assignee_id) and UNIQUE(report_id,kind,assignee_id). Typed tasks must match target reviewer and target version, validated by composite key/DB guard. Keep completed immutable history and no arbitrary generic target strings. Multiple attempt/round tasks remain distinct. Do not repurpose main current_step pointer for every parallel response. No requirement that a report task belongs to current global editor step: its explicit own StepRun is independently auditable.

## Workflow and human authority

Handling editor confirms opening round+first in-app invitations in one full snapshot; can confirm additional invitations to same fixed round (decline permits new attempt; submitted does not). Response/report are independent reviewer tasks, each explicit final human confirmation; acceptance before any file/text/model access. Primary manuscript phase projects reviewer_selection while no active accepted/reported reviewer, peer_review when at least one accepts. Editor's management StepRun/WorkItem stays independent of parallel reviewer task changes. Reaching required submitted reports does not accept the manuscript or invent editor completion. It enables explicit editor finish_review confirmation, listing remaining invitations/tasks to cancel and reason; then closes round/revokes grants and creates editor_recommendation responsibility. Main final chief decision is E and remains absent in D.

Reviewer serializer is an explicit allowlist: anonymous title/abstract/keywords/scope, own invitation/round/form/report, and only authorized round files after acceptance. Pending only invitation summary; no authors, emails, institutions, original filenames, uploader/actor IDs, other reviewers/reports, private staff report data, or broad audit. Closed own report history may be read through a narrow DTO but no later/new files. Core/API/model/download and conversation history/replay all consume the same scope. Preserve exposure dependencies finer than manuscript existence: losing accepted file grant must not keep full-text transcript readable just because invitation summary is still visible. Unknown raw report endpoint always denies author, even after later release.

Author sees actual stage and own versions but no unreleased report IDs, reviewers or private recommendations. Production scope remains separate later. All mutations use lead's Action Gateway, role/journal/assignment/COI/revision checks, same transaction audit and receipts; model can prepare candidates/proposals but no final confirmation.

## Incremental acceptance

Frozen-round compound FK/immutability/confirmation binding; same reviewer re-invite after decline; explicit acceptance and COI; private/anonymous API + file headers + model/history/replay; draft vs submitted counting; wrong recipient/role/journal/version, expired/stale/concurrent transitions, atomic rollback; full existing regression. No direct SQL seeded final states for browser: extend existing author→editor→chief→quality chain into actual invitation response and report confirmation. Test decline/re-invite and target counts separately. Model/DDL helper tests do not establish service/UI completion.

## Proposal payload/guard convention

Open/invite confirmation payload uses `review` object with round_id, round_no, version_id, required_reports, form_snapshot, form_digest, material_digest, files[{version_file_id,sha256,role,display_name}], invitations[{id,reviewer_id,attempt_no,invitation_snapshot,response_due_at,report_due_at,content_digest}]. Action types are open_review or invite_reviewers. IDs are allocated at prepare and fixed in the full immutable snapshot. Initial RoundFile insert occurs only while initializing; sealing compares submitted set to opening payload (ordered deterministic IDs), frozen VersionFile metadata and actual hashes rechecked in gateway. Dates normalized ISO8601 UTC.

Respond action uses response {invitation_id,outcome:accept|decline,conflict_status:none|declared,notes}, exact target snapshot and version. Submit-review action uses review_report {id,invitation_id,form_digest,data:{author_text,editor_private_text,answers_json,recommendation},content_digest}. Finish-review uses review_closure {round_id,reason,submitted_report_ids,cancel_invitation_ids}; workflow/task mutations and cancellations listed before human confirmation. Do not require a database trigger to infer unknown frontend naming: coordinate deviations before coding guards.

Closing uses explicit Round.closing_confirmation_id, required on closed and bound to finish_review/current revision/full closure snapshot. Whole-round cancelled is reserved and unsupported until a separate authorized operation exists. Single cancel_review_invitation also uses review_closure, exactly one cancel ID plus actual current submitted report IDs/reason. Submitted invitations cannot cancel.
