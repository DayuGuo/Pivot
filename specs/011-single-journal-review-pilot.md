# 第一阶段：单人＋Codex的单刊审阅试点

2026-11-03优先级修正：本计划现在位于[spec012展示Demo](012-showcase-demo.md)之后；8周与现金预算指真实受控审阅试点，不是展示型项目的前置成本。本地静态Demo先演示日历/双层对话等思路，不表示这些功能已接入真实任务数据库，也不解除此处人工专业复核与数据授权条件。

日期：2026-11-03。状态：执行计划与预算，尚未实现或采购。依据最新用户要求，近期优先级收敛到本规格；完整产品蓝图仍见 [PRODUCT_DESIGN.md](../PRODUCT_DESIGN.md)。原v0.1合成工作流保持现状，不作为新审阅能力已经完成的证据。

## 1. 交付目标与边界

由用户本人担任产品负责人和主要开发者，Codex辅助实现与测试；专业工程师阶段性独立复核，不组建五人全职团队。

第一阶段只交付一条真实可操作闭环：

**指定编辑登录 → 录入一本期刊的完整稿件与作者元数据 → 核对解析内容与覆盖范围 → 围绕当前版本只读问答 → 点击原文与外部记录证据 → 刷新/重启仍可恢复。**

使用20篇合成或公开且明确获准使用的非保密样本，邀请3—5位编辑参与；不替换原投审稿平台、不承担正式审稿决定。第一阶段全程不导入真实保密在审稿件。专业复核与校方样本授权通过前只做本地测试，不自动部署；复核通过也不自动解除现有保密稿件/模型出域限制。

计划8周，以本人每周30—40小时有效投入、现有电脑与代码可用、编辑能持续反馈为前提；预留延长到10—12周的可能。按验收放行，不承诺到日期就上线。

## 2. 最小范围

| 必须完成 | 第一阶段的具体限制 |
| --- | --- |
| 一本期刊、少量账号 | 手工开通指定编辑，明确每篇资料的访问者；不开放注册，不建多角色切换产品 |
| 完整原始文件 | 原件与版本/hash持久保存；支持TXT/MD、文字型PDF及基础DOCX；暂定单文件20MB、PDF50页及20位作者上限，超限明确拒绝而非截断 |
| 解析与核对 | 正文、段落、普通表格文字、图注及参考文献可查看；标明缺页/不可提取内容、解析失败与覆盖范围 |
| 作者与稿件元数据 | 题名、摘要、关键词、语言、作者顺序、机构对应、通讯作者、联系邮箱、ORCID及其提供来源；人工核对保存 |
| 版本化资料包 | 录入/处理中/待补齐/可进行文字审阅/部分不可读；修改后新修订或新版本，旧回答仍指向旧依据 |
| 单稿只读问答 | 问方法、样本、结果、作者元数据和参考文献；只读取有权材料，不准备业务决定或自动修改字段 |
| 本稿证据 | 段落/章节或实际PDF页定位、文件与版本、准确引用片段；无页码的格式不编造页码 |
| 最小外部证据 | 仅核对已提供ORCID与参考文献DOI；ORCID官方记录链接、首个DOI元数据适配器及缓存/核验状态 |
| 可恢复与可审计 | 私有对话、来源和版本持久化；错误安全处理、API超时/额度上限、备份恢复及自动化回归 |

“完整文件已上传”和“模型理解全部内容”分别标识。第一阶段不做扫描稿OCR、复杂公式识别、图像科学解读、复杂排版/修订痕迹还原；原图等材料仍保留供人阅读。若文稿的关键结论只能从未解析图表取得，明确不能回答；不能把该稿标为完整自动理解。

DOCX不假定能获得真实排版页码，按文本长度、解压体积及结构复杂度限制，引用使用章节/段落/表格位置；具体上限在G1定稿。

必要元数据缺失不能显示“资料齐全”。ORCID按期刊规则允许未提供，但必须明示；手填号码、校验格式/校验位、官方记录存在、作者控制该iD是不同事实。暂不做ORCID OAuth登录，也不假装已经认证作者身份。

### 暂缓内容

日历、多期刊/多身份、跨刊邀请中心、主对话跨稿调度、邮箱/ORCID自助注册、自动挑选审稿人、完整同行评审与编辑决定、真实邮件、DOI注册、正式公开出版、排版制作、批量历史迁移、GPU本地大模型、多Agent自治和全网人物/文献发现。

已有旧功能不为试点删除或降低测试要求；试点入口的后端权限只允许所需能力，不能只靠隐藏旧按钮限制操作。

## 3. 利用现有代码，补真实缺口

| 可复用基础 | 新阶段仍须建设 |
| --- | --- |
| Next.js三栏、FastAPI、PostgreSQL/Alembic | 专用编辑资料录入和只读审阅入口 |
| 登录、CSRF、对象权限与审计 | 试点账号的最小能力与每稿访问分派 |
| 版本、作者快照、实际UTF8内容寻址存储 | PDF/DOCX的受限上传、隔离解析、位置与覆盖记录 |
| 实际文件引用、对话恢复和受控模型传输 | 文档检索、逐条证据校验、来源面板及外部记录适配器 |
| 现有835后端/35浏览器回归 | 新解析/引用质量/权限/外部失败和真实样本验收 |

当前files.py仅接受1MB以内UTF8 TXT/MD；不能把增大扩展名白名单当成PDF/DOCX支持。作者元数据已有ORCID字段，但没有外部认证或机构/成果核验。

当前私人作者准备稿不对任意编辑开放。新增“编辑录入的内部审阅资料”必须有明确来源和权限，不伪造作者已正式投稿，不通过扩大现有author_draft访问权绕过策略。内部资料与正式投稿的具体关联、复用哪些实体，在第1周专业复核时定稿；不先建另一套无法迁移的稿件数据库。

## 4. 最小技术路径

1. 原始文件私有保存，验证真实类型/大小，解析在受限进程或worker中执行；禁宏/脚本执行，限制CPU、内存、时间和DOCX解压规模。
2. 解析文本按版本、章节、段落切块并保存原文位置；先用现有PostgreSQL及简单检索完成中英文样本评测，不先建设复杂检索基础设施。
3. 用结构化元数据与检索片段构建本轮可见资料，只读回答；模型可以归纳，不能访问任意路径、执行代码或调用业务写工具。
4. 证据ID、URL与核验状态由后端登记，返回前核对所引用文件/段落确实属于该版本且仍有权限；网页能打开不等于内容匹配。
5. 外部适配器只接收合法标识符、访问指定官方接口；暂不对模型提供任意URL抓取。DOI题名/作者/年份不一致或有多个候选时，保留待核实状态，不静默认定。
6. ORCID以提供来源、规范链接和可访问/人工核对状态为起点；自动读取记录须符合实际接入权限。无法取得记录时明示未核实，不绕过访问限制；不把元数据录入当作身份认证。
7. 回答、证据、导入与人工修改留审计；对话本身允许持久化，但不会改变稿件工作流或正式deadline。真实邮件和最终决定仍不可调用。

跨版本历史、数据出域和提示注入沿用现有安全合同。未经授权的保密全文不发给模型或外部检索；公开API不能被假定可以无限或无条件商用。缺真实模型/接口凭据时用明确Mock进行本地开发，真实验收另列，不冒称成功。

## 5. 八周开发计划

| 周次 | 用户＋Codex完成什么 | 当周可检查的结果 |
| --- | --- | --- |
| 第1周 | 选定期刊/编辑与20篇获准样本，冻结字段、边界和100题评测草案；审计现有权限/数据复用 | 样本清单、字段表、精确接口/迁移设计；完成G1复核 |
| 第2周 | 编辑录入表单、作者顺序/机构/ORCID来源、原始文件及版本保存 | 实际录入/编辑/刷新恢复；未分派用户不能读 |
| 第3周 | PDF/DOCX解析、段落位置、解析任务状态、失败与部分覆盖 | 20篇逐篇检查提取结果；异常文件不挂死服务 |
| 第4周 | 章节检索与只读问答，本稿证据卡/原文跳转；去掉审阅路径的业务写能力 | 可问实际内容，答复引用准确文件/版本；完成G2复核 |
| 第5周 | 最小ORCID/DOI链接与记录匹配、缓存/时间/失败标记 | 实际官方记录存在/不匹配/不可访问各有样本，不生成假来源 |
| 第6周 | 固定评测集、恶意/无依据问题、版本/权限变化、浏览器恢复与回归 | 形成可复跑结果及失败清单，修复后重测 |
| 第7周 | 候选试点环境、私有文件、账号/密钥、日志脱敏、备份恢复及限额 | 完成G3；从实际备份恢复数据库和文件，移除公开demo访问能力 |
| 第8周 | 专业复核通过且校方授权后，3—5位编辑受控试用；修复阻断项 | 一条完整录入→审阅→点击证据→刷新恢复演示，编辑签收或明确延期 |

每天以一个可复现小改动为单位运行Research→Plan→Implement→Test→Review→Fix。Codex承担代码草稿、测试和文档；用户负责样本定义、阅读差异、核对结果和优先级。每周至少一次真实编辑反馈，避免最后才发现解析与问答不适用。

前4周以本地样本开发为主；不能因专业复核排期未到而停下可逆实现和合成测试。专业关口约束真实数据试点放行，不要求每次本地修改都请求批准。

## 6. 必须请专业工程师独立复核的关口

这里的“必须”是本阶段选择的试点放行条件，源于用户要求；不是声称所有原型开发都需要某种法定认证。Codex自评、原代码作者自评和测试数通过不能替代独立人工复核。

| 关口 | 时间与预计投入 | 复核重点 | 未通过时 |
| --- | --- | --- | --- |
| G1 数据与权限方案 | 第1周，约1天 | 内部录入与正式投稿分离、作者隐私、每稿分派、版本/证据关系、迁移与数据兼容 | 修正方案；不扩大真实数据访问 |
| G2 文件与证据执行路径 | 第4—5周，约1.5天 | PDF解析隔离、DOCX解压/资源限制、恶意文档/提示注入、检索和跨版引用、外部地址/SSRF边界、只读接口无写工具 | 阻断不安全上传/接口，不用真实敏感资料 |
| G3 试点环境与恢复 | 第7周，约2天 | 身份/会话/下载鉴权、最小权限、密钥与日志、默认账号、TLS/网络暴露、实际备份恢复、模型出域范围及开销限额 | 不对真实编辑开放候选环境 |
| 复测与交接 | 第8周，约0.5天 | 阻断问题确实修复、回归证据、暂停/恢复与故障联系安排 | 缩小范围或延期，不带着问题交付 |

总计约5个专业人日，建议预留4—6天。由能独立检查Python/PostgreSQL/Web安全与部署恢复的资深工程师承担；遇到超出其能力的文件安全或基础设施问题，补专项人员。真实数据使用范围由校方有权负责人另行确认，工程师不能代替其授权。

每次复核应留下问题、严重度、相关代码/迁移、修复提交、复测结果与是否准入的记录。合同/采购若要求正式第三方测评，另行预算；本计划的代码复核不能冒称该类认证。

## 8. 第一阶段验收与停止条件

### 固定验收集

- 20篇样本覆盖中英文文本型PDF、基础DOCX及解析边界；扫描/超限等不支持材料单独作拒绝或部分覆盖样本，不算成功解析。
- 100个固定问题：40个正文事实/方法问题、20个作者/元数据问题、20个参考文献/标识符问题、20个缺证据/不匹配/恶意指令问题。
- 与编辑共同标注正确依据、可接受答复或应当拒答的原因；按版本固定，不能让模型自己判定自己全部正确。

### 放行要求

1. 录入完整原件和元数据，刷新/重启可恢复；解析失败不丢原件、不挂死服务，不支持的部分明确显示。
2. 本稿引用可打开对应版本/原文片段；旧版回答不串到新版本，撤权后的下载、消息和重放不能泄漏。
3. 外部核验必须有实际官方接口/记录验收，至少展示存在、匹配、不一致、无法核验各类情况。没有完成实际核验的适配器只标未验证，不用Mock充当真实链接证明。
4. 所有展示为有效证据的引用ID真实、授权正确且支持相应陈述；没有证据时承认不确定。链接可访问不冒称科学结论可靠或作者身份已认证。
5. 100题中至少90题由编辑评为可用（含正确拒答）；其余逐题有明确失败/改进记录。这是试点目标，不是已经测出的准确率，也不是自动学术审查保证。
6. 越权访问、虚构“已核验”来源、私密材料出域、任意文件/内网访问或执行关键动作，任一发现都阻断试点，修复并复核后再继续。
7. QA问题与恶意提示均不改变稿件流程，不调用邮件/最终确认；EMAIL_SEND_ENABLED=false。
8. 新增解析/证据/权限/只读问答测试、Playwright完整演示、既有scripts/verify.sh全部通过；实际从备份恢复数据库与文件，专业复核问题关闭，校方批准数据范围后才能试用。

第8周未达标则延长或收缩范围，不自动上线。若数据处理授权、必要外部接口权限或工程复核不能取得，继续合成/公开授权样本验证，不将阻塞伪装成正式试点成功。
